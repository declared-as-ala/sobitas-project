## 30–60 day monitoring plan

Every check below is **page-level**. A query-level average will mislead you here — that is precisely
the mistake this audit exists to correct.

**Weekly — Search Console → Performance**

1. Use the **Pages** tab, not Queries. Track `/creatine`, `/whey-proteine`, `/mass-gainers`,
   `/proteines`, `/bcaa`, `/vitamines`, `/pre-workout`. Position moves first; clicks lag it.
2. For each of `creatine tunisie`, `whey protein tunisie`, `mass gainer tunisie`: filter to the
   query, then open the **Pages** breakdown. You are watching for the category URL to appear and
   climb *while the blog holds* — not for the blog to fall. If the blog falls and the category has
   not risen, revert that cluster's title change.
3. **Device** tab: desktop sits at 17.9 against mobile 7.6 on the same URLs for the same queries.
   Watch whether the gap narrows as the rebuilt crawler-view link graph is recrawled.
4. **`?page=` URLs** were noindexed until today. Expect them in Coverage as "Indexed" within 2–4
   weeks. If they instead appear as "Duplicate without user-selected canonical", the de-duplication
   did not take — say so and it gets reverted.

**Fortnightly — Search Console → Indexing → Pages**

5. **"Excluded by noindex" should fall from 12,206.** That number is larger than the entire indexed
   set (6,190) and is the biggest structural signal in the property.
6. **"Page with redirect" (5,760)** should fall as the collapsed chains are recrawled.
7. **"Not found (404)" (633)** should fall as the renamed-product redirects take effect.
8. **"Redirect error" (31)** should reach 0 — that was the `/Intra-Workout` loop, already fixed.

**Fortnightly — Shopping and Enhancements**

9. **Merchant listings: 6 invalid** — worth fixing. Product snippets are 1,451 valid / 0 invalid.
10. **Breadcrumbs (1,434 valid)** — the trail now carries "Boutique" and the real parent category;
    confirm no invalid items appear after this deploy.
11. Google's own recommendation on the property: **"Your products are missing a return policy."**
    That is a Merchant Center field and it gates richer product results.

**Once, then monthly — Core Web Vitals**

12. **Mobile INP above 200 ms on 868 URLs** is the only failing CWV metric (LCP passes, desktop is
    entirely clean). This pass does not address it; it needs the hydration work listed under P3.

**What not to conclude.** Nothing here should move in week one. Titles and link graphs are recrawled
over 2–4 weeks, and the best-seller PDPs that were `noindex` from 11/08 to 21/09 are still
re-entering the index. Judge this pass at **20 October 2026**, not before.

### http://www.protein.tn/* is a 2-hop chain: Cloudflare 301 to https://www, then Next.js 308 to the apex

**Status:** `owner` · **Where:** `live https://www.protein.tn/creatine ; frontend/redirects.js:62-67 (www → apex rule) ; nginx/protein-tn-canonical.conf:20-31 (www server block, not in the serving path)`

- *Today:* Hop 1 is produced by Cloudflare ('Server: cloudflare', no X-Served-By, Location keeps the www host) — i.e. the zone's 'Always Use HTTPS' behaviour. Hop 2 is produced by Next.js: the https://www response carries `X-Served-By: www.protein.tn` and a `Refresh: 0;url=` header, which is the redirects.js host-conditional rule (308). The nginx www server block in C:/mla/nginx/protein-tn-canonical.conf that would answer both hops with a single 301 to https://protein.tn is evidently not what proxies www traffic (the request reaches Next).
- *Cost:* Any external link or old citation using http://www.protein.tn/… costs two redirects before Google reaches the canonical page. Chains are followed but slow consolidation and keep the www URLs in the 'Page with redirect' bucket; http→https and www→apex are the cheapest hops on the site to collapse.
- *Evidence:* Live 2026-09-22: GET http://www.protein.tn/creatine   301 -> https://www.protein.tn/creatine   (Server: cloudflare, cf-cache-status DYNAMIC) GET https://www.protein.tn/creatine  308 -> https://protein.tn/creatine       (X-Served-By: www.protein.tn, Refresh header = Next.js) GET http://protein.tn/creatine       301 -> https://protein.tn/creatine       (single hop, correct) GET https://protein.tn/creatine/     308 -> https://protein.tn/creatine       (Next trailing-slash, expected)
- *Fix:* Owner/edge only, no code change. In Cloudflare → Rules → Redirect Rules add one Single Redirect: expression `(http.host eq "www.protein.tn")`, type Dynamic, target `concat("https://protein.tn", http.request.uri.path)`, status 301, "Preserve query string" ON. Confirm the www DNS record is proxied (it is — Cloudflare already answers hop 1). Verify with a Googlebot UA: `curl -sI -A Googlebot "http://www.protein.tn/creatine?x=1"` must return a single 301 with `Location: https://protein.tn/creatine?x=1` and `Server: cloudflare`; repeat for https://www.protein.tn/creatine and for the homepage.
