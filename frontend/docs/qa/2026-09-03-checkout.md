# Checkout usability and recovery — 3 September 2026

## Scope

Mature storefront; keep the contact → delivery → cash-on-delivery journey. Required full name,
phone and address; email stays optional. Reuse Input, Button, AddressSelector, Sheet, Container
and existing tokens. No new dependency or promotional artwork. No change to pricing, stock,
loyalty eligibility, SMS or mail credentials.

Visual polish: familiar lucide icons, 48px inputs with 16px text, shorter payment explanation,
native mobile address selectors, removal of duplicate headings and unavailable card option.
Phone CTA remains available; inline submit remains usable while the keyboard hides the fixed CTA.
Both themes use the existing palette. CheckoutPage now has zero design-lint violations.

Named behavior changes: centralized validation, first-error focus after React commits the message,
inline descriptive errors with aria-invalid/aria-describedby, live announcement, no native-browser
validation tooltip competing with custom errors. Immediate scroll prevents moving tap targets and
supports reduced-motion preferences. Editing removes the old error; submitting revalidates.

Network recovery preserves form/cart and idempotency key for unchanged retries. A synchronous lock
blocks rapid repeated submits. Address-data failures have an explicit retry and bounded timeout.
Known account data fills only untouched empty inputs. Coupon work cannot race order submission.
Optional email accepts blank; pasted Tunisian phone formats and Arabic digits normalize safely.

The order proxy now forwards backend field errors. Guest checkout receives its order capability
token in the create/replay response and uses it to fetch authoritative confirmation without requiring
email. The details route still refuses missing/wrong capabilities; tokens are not in details responses.
Confirmation maps the backend product relation and includes delivery address fields.
