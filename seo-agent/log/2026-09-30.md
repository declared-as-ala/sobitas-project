## The defect: "one link per destination" was enforced against only half the links

`frontend/src/util/internalLinks.ts` turns the first mention of a category in a blog article into a
link. Its header states the limits that keep it from being spam, first among them:

> ONE link per destination — the second link to /proteines in the same article adds no signal and
> dilutes the anchor text of the first

It was enforced against **its own** insertions only. The bodies are CMS HTML and many already carry
an author's own anchor to a shelf; the tag walker correctly refuses to link *inside* that anchor,
then links the same shelf again from a different mention a paragraph later. The caller already
applies the right rule for the one case it knew about — `blog/[slug]/page.tsx:404` drops the
commerce bridge's own destination from the target list, "that dilutes the article's one clear job"
— so this is the same policy, applied to the case it was missing, not a new one.

**Measured on production, all 223 published articles** (Googlebot UA, links inside `<article>`
only, injected ones identified by `class="article-inline-link"`, destinations normalised for
origin / trailing slash / query / case):

| articles shipping an injected link to a destination the body already links | **31** |

**24 of 37 are on `/proteines` and `/whey-proteine`** — the two pages behind the two largest rows in
`KEYWORDS.md` (`proteine tunisie` 683 impr at 18.5, `whey protein tunisie` 346 at 15.7, both

The worst case is **`/blog/whey-protein-en-tunisie`** — the article that header names — at the cap
and wasting **two** slots (`/whey-isolate`, `/creatine`). And
`/blog/whey-proteine-prix-en-tunisie-comparatif-et-meilleurs-offres`, which today's SERP look found
ranking in the same set as `/whey-proteine` itself, is at the cap wasting slots on
`/whey-proteine` **and** `/proteines`.

**The fix** seeds the `used` set from the destinations the incoming HTML already links, through a
normaliser so the four ways a CMS body writes one shelf all compare equal:

```
https://protein.tn/proteines   /proteines/   /Proteines   /proteines?ref=blog   →   /proteines
```

`placed` only counts real insertions, so the slot a duplicate used to burn now goes to the next
destination with no link at all. An href on another domain is not a site path and suppresses
nothing.

**Proved able to fail before being trusted** — the same five cases against the old builder and the
new, using the real function through a resolve hook (no reimplementation):

| case | old code | new code |
| --- | --- | --- |
| body already links /prise-de-masse twice (relative + absolute) | injects a 3rd — **FAIL** | injects /proteines, /whey-proteine, /creatine instead — ok |
| body links `https://www.protein.tn/proteines/?ref=blog` | injects /proteines — **FAIL** | suppressed, /whey-proteine still placed — ok |
| body links `/Proteines` (uppercase) | injects /proteines — **FAIL** | suppressed — ok |
| clean body (regression guard) | 3 links | **3 links, identical** |
| external `https://example.com/proteines` (regression guard) | 2 links | **2 links, identical** |
| idempotence (run twice) | stable | stable |
| | **3 FAILURES** | **ALL CASES PASS** |

The two regression guards matter as much as the three failures: a gate that fires on the clean case
would be a gate that breaks the feature.
