## The defect: the builder shortens a title on one of its three tails

`humanProductTitle` in `frontend/src/util/productMetaDescription.ts` builds three shapes, and only
one of them ever reached the shortening code underneath:

```
  if (tail === 'Protein.tn' && brandRaw) return base;   // name already carries its brand → returned early
  const full = `${base} | ${tail}`;
  if (full.length <= 65) return full;
  if (tail === 'Protein.tn') return base;               // no brand at all → returned after the test
  const budget = 65 - …                                 // ← the trim only ever ran below here
```

**Measured, not estimated.** The real builder was imported and run over the real catalogue —
11,353 products through `productsBySubCategoryId/<slug>` for every listing in `listings.xml`:

| | before | after |
| --- | --- | --- |
| titles > 65 characters | **3,240 (28.5 %)** | **103 (0.9 %)** |
| longest title | **169 chars** | 65 |
| titles changed | — | 3,142 (27.7 %) |

The worst was *"Sambucus Black Elderberry Immune Complex Plus Vitamin C & Zinc, Natural Mixed Berry,
60 Chewable Tablets – Sambucus Black Elderberry Immune Complex Plus Vitamin C & Zinc"* — 169
characters, of which Google shows about 60. Everything that answers the query (the format, the
"Prix Tunisie") sat past the cut.

**The 103 that remain are deliberate.** They come from the CMS/DB `explicit` path, not the builder
(97 measured by route), and several are the backend duplicating the product name inside its own
title. The standing rule is that a title a person wrote in the CMS wins, so the frontend does not
override it; that is backend content and it is already BACKLOG P2 (`ImportedProductContent.php`).

**The fix** applies the same computation to every path (`fitTitleName`), and rewrites the trim so it
removes whole words from the end *until the title actually fits* — the old arithmetic estimated the
budget once and overshot it by up to six characters. It also tidies the seam a cut leaves, which the
first version of this fix did not, and the samples showed why:

| before the seam fix | after |
| --- | --- |
| `… Buffered Vitamin C with – Prix Tunisie` | `… Buffered Vitamin C – Prix Tunisie` |
| `… Korean Ginseng – 100 – 550 mg – …` (unit cut away, bare number left) | `… Korean Ginseng – 550 mg – …` |
| `… EarthSweet Chewables, – 1 mg – …` | `… EarthSweet Chewables – 1 mg – …` |

The format segment ("300 g", "60 caps") is kept and dropped **last**, because the format is what
Tunisians type — Monday's `suggest.mjs` run found the whole long tail is format + prix. The bare
number is only removed when a separator introduced it, so "Zumub Omega 3" keeps its 3.

**Verified over the whole catalogue, before shipping:**

| check | result |
| --- | --- |
| every rewritten title ≤ 65 characters | **3,142 of 3,142**, p50 60, max 65, none empty |
| none ends on a separator or connector | 0 of 3,142 |
| **in-stock products (qte > 0) whose title changes** | **0** |
| **watchlist / 05-10-freeze PDPs whose title changes** | **0** |
| casing contract over 11,379 live names (rules a–e) | ok, unchanged |
| `npm run typecheck` · `lint:design` · `check-url-contract` | clean |

That 0/0 pair is the important line: **the freeze is untouched by construction, not by intention.**
Every title this changes belongs to an out-of-stock imported long-tail product. Not one buyable
product, and not one page under the 05/10 freeze, renders a different `<title>` because of it.

## The second defect: the gate that guards this builder had gone blind

`title-case-check.mjs` loads the real builder through a resolve hook so the file under test is the
file that ships. On 28/09 the builder gained `import { DELIVERY } from '@/util/company'`, the hook
resolves relative specifiers only, and Node could no longer load it. Since then the tool has
answered:

```
could not measure: cannot load the builder (Cannot find package '@/util' …)
```

— **exit 2**, which by its own design is never a P0 and never fails a run. So the Friday casing
contract, written precisely because "the next edit to `caseToken` can silently undo the fix and the
only place it would show is the SERP, weeks later", has been asserting **nothing** for a day, in the
quietest possible way. The hook now resolves the `@/*` → `frontend/src/*` alias. It reads
11,379 names again and the contract holds on every rule.

**And a new rule (f): the title must fit 65 characters on every tail.** `FROZEN_TITLE_MAX = 65` is a
frozen copy of the builder's constant, never an import of it — the same doctrine as
`FROZEN_KEEP_UPPER`, for the same reason: a check that reads its expectation out of the thing it
checks cannot catch that expectation being deleted. Only the builder's own path is judged; a CMS
title is out of scope.

**The gate was proved able to fail**, which is the only thing that makes a gate worth having. Run
against the *old* builder over 421 products: `f | **283 FAIL**`, exit 1. Against the new one: `ok`.

## Deliberately NOT done

- **No title, H1, robots or canonical change on any money page**, and no change to any in-stock
  PDP. The 05/10 freeze holds — verified by measurement (0 of 0), not asserted.
- **No override of the 103 long CMS titles.** "A title a person wrote in the CMS wins" is a standing
  decision; the fix for those is in the backend and it is already in BACKLOG.
- **No comparison table** on the 8 categories missing one. With 2–7 buyable SKUs the table would say
  almost nothing; it is queued behind the stock.
- **No cap on `humanProductHeading`.** The H1 and `Product.name` keep the full humanised name: an
  H1 has no SERP budget, and shortening it would cost the shopper the words the title had to drop.
  A `<title>` shorter than its H1 is ordinary, and is not the "three different names" defect in
  BACKLOG P2 — that one is about the raw shouting string, which the owner fixed on 28/09.
- **No `resources/seo/products` entry**, so `ops/queue.txt` stays empty — a `seo-copy-apply` with
  nothing to apply is a wasted VPS run.
