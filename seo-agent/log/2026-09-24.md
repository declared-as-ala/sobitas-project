## What I changed, and why — `frontend/src/util/productMetaDescription.ts`

`humanizeProductName` exists for the wholesaler style the catalogue is full of
(`100% CREATINE MONOHYDRATE 300G - BIOTECH USA`). Its own comment says "only the auto-generated
shouting ones are rewritten" — but that guard is on the stored **title**, not on the **name**, so
the token caser ran on every name in the catalogue, including the thousands of iHerb imports that
are already correctly cased. It was destroying capitals rather than repairing them.

I measured it instead of guessing. Pulled **7,389 real product names** from
`productsBySubCategoryId/<slug>` across 42 listings (of 11,367 in the sitemaps) and ran the actual
builder over them with `node --experimental-strip-types`:

- **243 names (3.3 %) are shouting** — the humanizer's real target.
- **4,699 were being re-cased.**

Three fixes, all inside this one file:

1. **Re-case only a name that is shouting** (majority uppercase) **or entirely lower case.** A
   name that already carries intentional capitals keeps them. Unit normalisation, mojibake repair,
   the brand-tail strip and the separator tidy are casing-independent and still run on every name.
2. **`KEEP_UPPER` lookups are punctuation-aware.** Tokens are split on spaces, so they arrive as
   `"HMB,"` and `KEEP_UPPER.has("HMB,")` is false — `MuscleTech Clear Muscle, Liquid HMB, 84
   Liquid Softgels` shipped as `Liquid Hmb,`. The punctuation is now peeled off, the core cased,
   the punctuation put back.
3. **Six brand initialisms added to `KEEP_UPPER`** — `GSN HX MND JX BPI IHS`, taken from the
   shop's own brand table and limited to the ones I measured flattened inside shouting names
   (25 products). None is a word in French or English, so none can catch an unrelated token.
4. **The glued-unit rule now matches lower case** (`(\d+)\s*[Gg]\b`), with a lookbehind so a token
   that merely ends in digits (`B12g`) is not split. This is the one that fixes the 0-click page.
