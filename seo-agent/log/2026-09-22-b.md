## Finding — the one that mattered: ~2,850 words of the money categories were bot-only

BACKLOG's first P0 ("bot/human parity on money categories, cloaking exposure") was written from
reading the code. I measured it instead, live, both UAs, 6-word-shingle diff of the visible text
(`seo-agent/tools/parity-check.mjs`, new today):

| page | bot words | human words | **bot-only words** |
| --- | --- | --- | --- |
| /creatine | 2,944 | 3,133 | **369** |
| /whey-proteine | 3,287 | 3,256 | **635** |
| /mass-gainers | 3,155 | 2,564 | **967** |
| /pre-workout | 2,893 | 2,736 | **690** |
| /proteines | 1,812 | 2,342 | **187** |
| | | | **2,848** |

Cause, confirmed to within a few percent on every file: `CategorySeoLanding.tsx` L111–115 prints
`htmlToText(intro, 520)` behind a 2–3 line clamp, and L183 rendered the intro in the guide column
**only when no buying guide existed** (`hasHowTo ? guide : intro`). The intros are far longer than
520 characters — creatine 2,936 · whey 4,438 · pre-workout 5,246 · mass-gainer 7,673 — so
everything past character 520 reached nobody. `CrawlerCategoryView.tsx` L105–112 prints `introHtml`
whole, and middleware rewrites bot UAs to it. **49 of the 50 category content files carry both an
intro and a guide**, so this was every category we own a page for, not four pages.

That is the parity break dynamic rendering is not allowed to have, on exactly the pages that have
to rank. It is also a straight loss to shoppers: the price paragraph, the format comparison and
the delivery paragraph were written for them and they could not read them.

## What I changed, and why

**A. `frontend/src/app/(shop)/category/CategorySeoLanding.tsx` — the intro renders in full, to
everyone.** One guarded block added at the top of the below-fold guide section: when a category
has BOTH an intro and a guide, the intro is rendered whole above the "Conseil d'achat" heading,
separated by a `border-b border-rule` (the same prose class string the guide column already uses,
so the file stays at **zero** design-lint violations — it is not in `design-baseline.json`).

**B. `seo-agent/tools/audit-live.mjs` — the canonical rule compared against the wrong URL.**
Today's audit reported `1 P0: /Intra-Workout/… canonical → /intra-workout/…`. That page is
**correct**: it is in `watchlist.txt` on purpose, as the proof that the uppercase form 301s once
and stops, and the right canonical for a redirect source is the redirect *target*. The rule
compared the canonical to the path *requested* instead of the one *served*, so the fixed page was
going to be a P0 every single morning — and a P0 that is always red is a P0 nobody reads. Now
compared against `res.url`. Where nothing redirects the two are identical and the check is
unchanged; a page that serves 200 at the wrong path with a canonical elsewhere is still a P0.
Re-ran the watchlist audit after the fix: **exit 0, zero P0**.

**C. `seo-agent/tools/parity-check.mjs` (new).** Read-only, no credentials. Fetches each path as
Googlebot and as Chrome, strips script/style/svg/noscript/comments, decodes entities and diffs
6-word shingles — shingles, not word counts, so reordering a block is not a finding and two renders
with equal totals can still be caught. **Only bot-only text is budgeted** (60 words): human-only
text is the crawler route working as designed (it has no header, footer, facets or sort controls),
so it is printed as context and never as a verdict. Exit 0 pass · 1 finding · 2 could-not-measure
(never a P0). Crawler pager and breadcrumb wording are ignored by name. Its pre-change run is the
