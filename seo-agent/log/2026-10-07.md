### The fix is a stricter rule, not a silenced one

`audit-live.mjs` now carries a **frozen copy** of the 18 mappings and asserts the canonical equals
the **declared target**; everything else still has to be self-canonical.

**Why a frozen copy and not an import of the config** — the lesson `title-case-check.mjs` already
records for `KEEP_UPPER`: *a check that reads its expectations out of the thing it checks cannot catch
a deletion*. The config's own header says removing an entry "reverts that product to a self-canonical
on the next render", so an importing checker would simply expect self, pass, and the consolidation
would evaporate unnoticed. Against a frozen copy the same deletion makes live disagree with
expectation and raises a P0 — which is exactly what 05/10 wanted. It also catches a variant
re-pointed at the *wrong* target, which the old rule could not see at all.

**Proved able to fail**, end to end against the real production page:

| test | expectation | result |
| --- | --- | --- |
| healthy live variant | P2 "expected", exit 0 | **P2 `declared variant → …2-27kg (28/09 consolidation, expected)`, exit 0** |
| frozen copy repointed at the 908 g | P0, exit 1 | **P0 `…expected …908g — the 28/09 consolidation regressed`, exit 1** |
| entry deleted from the frozen copy | P0, exit 1 | **P0 `canonical → … (served …)`, exit 1** |

The third test is the one that matters: delete the declaration and the **strict old rule comes
straight back**, so this did not become a blanket "ignore non-self canonicals". Full audit after the
fix: **95 URLs, exit 0**, with the variant recorded as a self-documenting P2 instead of a false P0.
